Guide

open the explorer

The explorer runs your NumPy function once and shows you the mathematics it computes. This page explains what you are looking at.

Writing a program

Type a function on the left. The rightmost pane updates as you type. The last function you define is the one that gets traced, so helpers above it are fine.

def weighted_rms(x, w):
    return np.sqrt(np.sum(w * x**2) / np.sum(w))

np, numpy and sympy are already imported. Each parameter is filled with a sample array of length 5, so a function of two parameters gets two arrays. You do not pass inputs yourself.

Your code is never uploaded. Python, NumPy, SymPy and scikit-verify are downloaded into your browser and everything runs there.

Reading the output

The four tabs on the right are four views of the same trace.

tabwhat it shows
math The formula, typeset. Below it, the conditions the formula depends on and any compiled call that was sealed rather than traced.
steps The derivation, one operation per line, with back references between steps. This is the closest thing to reading the lowered form of your program.
cse The same derivation with shared subexpressions pulled out into t0, t1 and so on.
value The concrete number the code returned on the sample inputs, the traced shape, and the formula as plain SymPy you can paste elsewhere.

Steps, in detail

For the weighted rms above, the steps tab reads:

step 0: w[i]
step 1: x[i]
step 2: x[i]**2
step 3: step[2]*w[i]
step 5: Sum(w[j]*x[j]**2, (j, 0, 4))
step 6: w[i]
step 7: Sum(w[j], (j, 0, 4))
step 8: step[5]/step[7]
step 9: sqrt(step[8])
result: sqrt(step[8])

Each line is one operation the tracer saw. Numbers can be skipped where a step was folded into another.

Conditions on the result

When your code branches on the data, the branch it took becomes part of the answer instead of disappearing. Try the median example. The formula comes back as a single entry of the array, followed by the comparisons that had to hold for that entry to be the median.

This is the point of the tool. A formula without its assumptions is not a complete answer, so the assumptions are reported with it.

Refusals

Some operations have no exact symbolic form. Rather than return something approximate, scikit-verify refuses and says why. Try the refusal example, which casts to int partway through:

astype to non-float would change the math

A refusal is a designed outcome, not a crash. The rule is to return an exact expression or to refuse, because a plausible but wrong formula is the failure this project exists to prevent.

Sealed calls

Compiled routines such as LAPACK solvers cannot be traced through. They become named symbols, checked against their defining equation on the concrete arguments. A solve is checked against Ax = b, a singular value decomposition against U diag(s) V^T = A. When this happens the math tab lists the sealed call, so you can see exactly where the symbolic reasoning stopped.

Sharing

The copy link button puts your program in the URL. Opening that link loads your code into a new tab named shared. Nothing is stored on a server, the code travels inside the link itself.

What this page does not do

The explorer covers extraction, which is to_sympy. The library does more than this page shows.

  • Checking a formula you supply, with check_formula and the @specifies decorator, is not available here.
  • Branch exploration with explore() needs the Z3 solver, which is not loaded in the browser.
  • Arrays are traced at length 5. A result proven at one length is not thereby proven at another.
  • Checking is over exact arithmetic. A confirmed formula can still lose accuracy in floating point.

For those, install the library:

pip install scikit-verify
